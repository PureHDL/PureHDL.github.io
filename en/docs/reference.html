PipeHDL Language Reference

Pipeline-aligned hardware description — automated register insertion, stall/flush logic, and valid tracking.

1. Introduction

PipeHDL is a pipeline-aligned hardware description extension to PureHDL. In a conventional register-transfer level design flow, a pipelined datapath requires the designer to manually manage pipeline registers, stall and flush logic, and valid-bit tracking. PipeHDL inverts this model: the designer describes the dataflow, and the compiler automatically inserts pipeline registers between stages, generates stall and flush control logic, and tracks valid bits through the pipeline.

Changing pipeline depth becomes a single parameter change, eliminating the error-prone process of manually renaming and rewiring registers across stages.

2. Example

The following example implements a three-stage pipelined multiplier. The pipeline depth is controlled by a single parameter:

module pipemul #(WIDTH: u32 = 32, DEPTH: u32 = 3) (
    input clk: clock,
    input rst: reset,
    input stall: bool,
    input flush: bool,
    input a: u32,
    input b: u32,
    output out: u32,
    output valid: bool
) {
    pipe(DEPTH) {
        @0 {
            let prod = a * b;
        }

        @(DEPTH-1) {
            out = prod;
            valid = true;
        }
    }
}

To change this design from three stages to five stages, modify DEPTH: u32 = 3 to DEPTH: u32 = 5. The equivalent implementation in Verilog would require approximately 80 lines of hand-written register declarations, always_ff blocks, stall and flush multiplexing, and valid-bits shift registers.

3. Module Declaration

module ModuleName #(PARAM1: type = default, PARAM2: type = default) (
    direction port_name: type,
    ...
) {
    // body
}

Supported port directions: input, output, inout (default: input).

4. Parameters

Parameters are compile-time constants for width and depth configuration:

#(WIDTH: u32 = 32, DEPTH: u32 = 3)

Parameters may be overridden at compile time via -D flags:

phdlc build input.phdl -o output.v -D DEPTH=5

6. Pipeline Blocks

The pipe(DEPTH) block is the core construct. It contains one or more @N stage annotations:

pipe(DEPTH) {
    @0 {
        let intermediate = a + b;
    }

    @1 {
        let result = intermediate * 2;
    }

    @(DEPTH-1) {
        out = result;
    }
}

6.1 Stage Semantics

  • @N blocks contain pure combinational logic only.
  • A variable defined in stage @N and used in stage @M (where M > N) automatically receives M - N pipeline registers.
  • A variable used only within the same stage produces no registers (wires only).
  • Stage indices may be literals (@0, @2) or parameter expressions (@(DEPTH-1)).

6.2 Stall and Flush

  • Stall freezes all pipeline registers.
  • Flush clears the valid chain and resets all pipeline registers.

9. Generated Verilog Output

The PipeHDL compiler produces standard-compliant Verilog with the following characteristics:

  • Module ports map to input and output declarations.
  • Pipeline registers are implemented as reg with always_ff @(posedge clk).
  • Stage combinational logic uses continuous assignment (assign).
  • Valid-bit tracking is implemented as a shift register with stall and flush control.
  • Variable names are preserved with consistent mangling for cross-stage references.

10. Compiler Usage

# Compile to Verilog
phdlc build input.phdl

# Specify output file
phdlc build input.phdl -o output.v

# Override parameters
phdlc build input.phdl -o output.v -D DEPTH=5 -D WIDTH=16

# Inspect AST
phdlc ast input.phdl

12. Current Limitations

  • Single pipeline per module: multi-pipe support is planned.
  • Uniform stall: all stages stall simultaneously.
  • No struct, enum, or array types yet.
  • No foreign module (Verilog black-box) interface yet.
  • Valid bit must be explicitly set in the last stage.
