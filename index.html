PureHDL is a modern hardware description language built from the ground up to replace Verilog and SystemVerilog. Type-safe, synthesizable, and engineered for the chip design workflows of the next decade.

Design Principles

Eight pillars that guide every decision in PureHDL — from syntax to compiler architecture.

1

100% Synthesizable

No split between simulation and synthesis subsets. If it compiles, it can go to silicon. Every construct in the language is hardware-ready.

2

Time in the Type System

No reg vs wire. No blocking vs non-blocking assignments. Time is explicit — seq() for sequential, comb for combinational. One assignment operator, context determines semantics.

3

Type-Safe Hardware

Width mismatches, direction errors, combinational loops — caught at compile time. In<T> / Out<T> carry direction in the type. No implicit truncation.

4

True Generics

Not the parameter hack of Verilog. Typed generics with trait constraints, just like Rust. #(Width: UInt = 8) — type-safe at the parameter level.

5

Module Integration as a Primitive

Connecting modules should feel like calling a function. dma.mst = uart.slv — the compiler checks interface compatibility. No more hunting through port lists.

6

PPA Visibility

Annotations and type information let the compiler reason about timing, area, and power during code generation. pipeline Crc32: 4 stages — explicit, not emergent.

7

Incremental Compilation

Change one module → recompile only that module. No more hour-long full rebuilds. A modern compiler for modern workflows.

8

AI-Friendly

Every concept has one canonical form. Strong types serve as implicit specification. Deterministic mapping from code to hardware reduces LLM error rates.

PureHDL in 60 Seconds

Three examples that cover the core of the language.

counter.phdl 
module Counter #(
    Width: UInt = 8,
) (
    clk: In<Clock>,
    rst: In<Reset>,
    en:  In<Bool>,
    val: Out<UInt[Width]>,
) {
    // Sequential logic — no reg, no always, no <=
    seq(clk, rst) {
        if rst { val = 0 }
        elif en { val = val + 1 }
    }
}
fsm.phdl 
fsm(onehot) Controller {
    state Idle, Fetch, Decode;

    Idle  -> Fetch when start;
    Fetch -> Decode when done;
    Decode -> Idle;

    // Moore output derived from state
    out.busy = (state != Idle);

    // Entry/exit actions
    on_entry(Decode) { data_valid = true; }
    on_exit(Decode)  { data_valid = false; }
}
extern.phdl — Verilog FFI 
// Call existing Verilog IP directly from PureHDL
extern "verilog" {
    module VerilogFifo #(
        Width: UInt = 8,
        Depth: UInt = 16,
    ) (
        clk: In<Clock>,
        din: In<UInt[Width]>,
        dout: Out<UInt[Width]>,
    );
}

module Top (
    clk: In<Clock>,
    tx_data: In<UInt[8]>,
    rx_data: Out<UInt[8]>,
) {
    // Instantiate and connect — compiler checks types
    let fifo = new VerilogFifo(Width=8);
    fifo.clk  = clk;
    fifo.din  = tx_data;
    fifo.dout = rx_data;
}

PureHDL vs Verilog — Side by Side

See how PureHDL eliminates Verilog's verbosity and traps. Same hardware, half the code.

1. Counter — no reg, no wire, no always, no <=

✗ Verilog

// 17 lines, 4 keywords to learn
module Counter #(parameter Width = 8)
(
    input  wire       clk, rst, en,
    output reg  [Width-1:0] val
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            val <= 0;
        else if (en)
            val <= val + 1;
    end
endmodule

✓ PureHDL

// 9 lines, 0 new keywords
module Counter #(Width: UInt = 8) (
    clk: In<Clock>, rst: In<Reset>,
    en: In<Bool>, val: Out<UInt[Width]>,
) {
    seq(clk, rst) {
        if rst { val = 0 }
        elif en { val = val + 1 }
    }
}

2. Mux — comb replaces always @(*) + case

✗ Verilog

module Mux4 (
    input  wire [1:0] sel,
    input  wire [7:0] a, b, c, d,
    output reg  [7:0] out
);
    always @(*) begin
        case (sel)
            0: out = a;
            1: out = b;
            2: out = c;
            default: out = d;
        endcase
    end
endmodule

✓ PureHDL

module Mux4 (
    sel: In<UInt[2]>,
    a, b, c, d: In<UInt[8]>,
    out: Out<UInt[8]>,
) {
    comb {
        out = case(sel) {
            0 -> a,
            1 -> b,
            2 -> c,
            _ -> d,
        }
    }
}

3. FSM — first-class vs boilerplate

✗ Verilog

// Must manually maintain state encoding,
// state register, next state logic,
// and output logic — 3 separate blocks
localparam [1:0] IDLE = 0, FETCH = 1;
reg [1:0] state, next_state;

always @(posedge clk)
    state <= next_state;

always @(*) begin
    case (state)
        IDLE:   next_state = FETCH;
        FETCH:  next_state = IDLE;
    endcase
end

assign busy = (state != IDLE);

✓ PureHDL

// Everything in one block. Compiler
// generates state register, next-state
// logic, and encoding automatically.
fsm(onehot) Controller {
    state Idle, Fetch;

    Idle  -> Fetch when start;
    Fetch -> Idle;

    out.busy = (state != Idle);
}

Bottom line: Verilog forces you to manage implementation details — reg/wire, blocking vs non-blocking, sensitivity lists, state encoding. PureHDL lets you describe what you want — the compiler handles the rest. Less code, fewer bugs, faster design.
