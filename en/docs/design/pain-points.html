Pain Points Analysis — Why PureHDL Exists

分析现有 HDL 的核心痛点，指导 PureHDL 的设计取舍。

1. Verilog / SystemVerilog — 40 年的历史债

1.1 reg vs wire 的原罪

Verilog 
reg [7:0] cnt;       // 你以为这是寄存器
wire [7:0] result;   // 你以为这是连线

// 实际上：
// reg ≠ register。reg = "过程赋值目标"
// wire ≠ wire。wire = "连续赋值目标"

reg 这个关键字名完全是误导。出师表里可以声明一个 reg 然后用在组合逻辑里，它根本不会变成寄存器。

SystemVerilog 加了 logic 来替代 reg，但 wire 还在用，现在变成三选一：reg / wire / logic。选择更多，困惑更多。

根本原因：语言的类型系统没有把"存储语义"和"赋值方式"分开。

1.2 阻塞 = / 非阻塞 <= 的陷阱

Verilog 
// 你以为行为一样
always @(posedge clk) begin
    a <= b;
    c <= a;
end
// 实际：c 拿到的是 b 的旧值，不是新值

Verilog 用赋值方式决定综合行为，而不是用声明表达意图。任何严肃的 Verilog 开发者都踩过这个坑。

1.3 敏感列表

Verilog 
always @(a or b) begin  // 忘加 c → 仿真综合不一致
    out = a & b & c;
end

1.4 parameter 不是类型安全的

Verilog 
parameter Width = 8;   // 不加范围
parameter Depth = 256; // 编译时传负数也不报错

1.5 generate 就是宏

Verilog 
generate
    if (WIDTH > 8) begin : gen_wide
        // ... 无尽的 begin/end
    end
endgenerate

1.6 include 文件地狱

Verilog 
`include "defines.v"
`include "constants.v"
`include "types.v"
`include "fifo.v"

2. SystemVerilog — 拯救还是灾难

SV 加了 interface、logic、assertion，但：

  • logic 不是 reg 也不是 wire，但有人还在用 wire logic
  • interface 不支持类型参数化
  • always_ff / always_comb 解决了敏感列表，但没解决 reg/wire 问题

3. 其他 HDL 的教训

3.1 Chisel

  • 输出 FIRRTL 不可读
  • 调试困难：生成网表和你写的 Scala 差异很大
  • Java 工具链：sbt 慢，JVM 重

3.2 SpinalHDL

  • 同样走 Scala/JVM 工具链
  • 文档差
  • 和 Chisel 一样不可读的输出

3.3 TL-Verilog

  • 基于宏的 DSL
  • 不是独立语言
  • 调试时需要展开宏

4. PureHDL 的回应

Pain Point PureHDL Solution
reg/wire No reg, no wire. Signal types inferred from context.
Blocking/non-blocking Single = operator. Context determines semantics.
Sensitivity lists seq(clk) / comb blocks. No lists to forget.
Weak parameters Typed generics with default values. #(Width: UInt = 8)
include / generate Module system with use, import, generics.
Unreadable output Clean Verilog output with 1:1 mapping.
No real interfaces Strongly typed interface with type parameters.
JVM toolchain burden Native Rust compiler. No JVM required.
Weak types Full type system: width, direction, clock domain.
