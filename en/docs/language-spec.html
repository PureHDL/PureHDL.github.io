PureHDL Language Specification

Syntax Design — Draft v3

1. Design Principles

The PureHDL language is governed by the following design principles:

  1. Everything is synthesizable. No split between simulation and synthesis subsets. Every construct that compiles is hardware-ready.
  2. Readable at a glance. A PureHDL module should communicate its function without requiring the reader to scroll through boilerplate.
  3. Types carry intent. Signal width, direction, and clock domain are encoded in the type system, not scattered across block boundaries.
  4. No Verilog baggage. The language eliminates always, assign, reg/wire, and the blocking/non-blocking distinction.
  5. One assignment operator. A single = operator whose semantics are determined by context: assignments inside seq() infer flip-flops; assignments at module level or inside comb are combinational.
  6. Time is explicit. seq() denotes sequential logic; comb denotes combinational logic. Mixed blocks are not permitted.
  7. Integration is a first-class concept. Connecting modules follows the same pattern as calling a function, with compiler-checked interface compatibility.
  8. Interoperability without inheritance. The extern "verilog" mechanism provides FFI without leaking Verilog syntax into PureHDL.

2. Module Declaration

A module is the fundamental unit of hardware description. The syntax for a module declaration is:

module ModuleName #(ParamName: Type = Default, ...) (
    port_name: Direction<Type>,
    ...
) {
    // body
}

Example — parameterized counter module:

module Counter #(Width: UInt = 8) (
    clk: In<Clock>,
    rst: In<Reset>,
    en:  In<Bool>,
    val: Out<UInt[Width]>,
) {
    seq(clk, rst) {
        if rst { count = 0 }
        elif en { count = count + 1 }
    }
    val = count;
}
Design note. The compiler infers signal types from context: a signal assigned inside seq() is automatically a flip-flop; a signal assigned at module level is automatically a wire. No reg or wire keywords are used.

3. Package and Import System

PureHDL uses a Rust-inspired module system. The standard library (phdl_std) is implicitly available:

use phdl_std::fifo::SyncFifo;
use phdl_std::axi::Axi4;
use crate::peripherals::uart::Uart;
use riscv_cpu::RvCore;

Visibility is controlled with the pub keyword:

pub module VisibleModule { ... }
module InternalModule { ... }
pub type PAddr = UInt[32];

4. Type System

4.2 Port Direction

Every port declaration includes an explicit direction wrapper. Naked types in port lists are not permitted:

module Something (
    clk:    In<Clock>,
    data:   Out<UInt[32]>,
    bidir:  InOut<UInt[1]>,
    a, b:   In<UInt[8]>,
)

4.3 Width Inference

The compiler infers result widths during evaluation. Implicit truncation is not permitted:

UInt[4] a;
UInt[4] b;
let c = a + b;       // c is UInt[5], carry bit preserved
let d = a + b[3:0];  // d is UInt[4], explicit truncation

4.4 Type Aliases

type Address = UInt[32];
type Data    = UInt[64];

5. Combinational Logic

Any assignment at module level is combinational:

module Add #(Width: UInt = 8) (
    a, b: In<UInt[Width]>,
    c:    Out<UInt[Width+1]>,
) {
    c = a + b;
}

Multi-statement combinational logic uses an explicit comb block:

module Mux4 (
    sel: In<UInt[2]>,
    a, b, c, d: In<UInt[8]>,
    out: Out<UInt[8]>,
) {
    comb {
        out = case(sel) {
            0 -> a,
            1 -> b,
            2 -> c,
            _ -> d,
        }
    }
}
The comb block enforces two invariants: (1) all outputs are assigned in all paths, preventing latch inference; (2) no combinational feedback loops exist.

6. Sequential Logic

Clock edges are declared on the seq block:

seq(clk) {
    // All assignments infer flip-flops on posedge clk
}

seq(clk, rst) {
    if rst { count = 0 }
    else   { count = count + 1 }
}

seq(clk.negedge, rst) {
    count = count + 1;
}

Multiple sequential blocks with different clocks are permitted within a single module:

seq(clk_fast) {
    fast_count = fast_count + 1;
}

seq(clk_slow) {
    slow_count = slow_count + 1;
}

7. Finite State Machines

7.1 Declaration

The fsm keyword provides first-class state machine support:

fsm Controller {
    state Idle, Fetch, Decode, Writeback;

    Idle       -> Fetch     when start;
    Fetch      -> Decode    when ready;
    Decode     -> Writeback;
    Writeback  -> Idle      when done;
}

7.2 Encoding

fsm(binary) Controller { ... }
fsm(onehot) Controller { ... }
fsm(grey)   Controller { ... }

7.3 Moore-type Outputs

fsm(onehot) Controller {
    state Idle, Fetch, Decode;
    Idle  -> Fetch when req;
    Fetch -> Decode when done;
    Decode -> Idle;

    out.busy = (state != Idle);
    out.we   = (state == Fetch);
}

7.4 Entry, Exit, and Transition Actions

fsm Controller {
    state Idle, Fetch, Decode;

    on_entry(Decode) {
        data_valid = true;
        cycles = 0;
    }

    on_exit(Decode) {
        data_valid = false;
    }

    on_transition(Idle -> Fetch) {
        addr_counter = 0;
    }

    Idle  -> Fetch when start;
    Fetch -> Decode when done;
    Decode -> Idle;
}
The fsm block infers the state register (auto-sized to fit the encoding), next-state logic, reset to the initial state (the first state declared), and Moore/Mealy output logic.

8. Interfaces

8.1 Interface Definition

interface AXI #(AddrWidth: UInt = 32, DataWidth: UInt = 64) {
    AWID:    UInt[4];
    AWADDR:  UInt[AddrWidth];
    AWVALID: Bool;
    AWREADY: Bool;
}

8.2 Direction from Usage

When used as Out<AXI>, all signals become outputs. When used as In<AXI>, all signals become inputs. Direction reversal is automatic:

module AxiMaster (
    clk: In<Clock>,
    mst: Out<AXI[32, 64]>,
) {
    mst.AWADDR = addr;
    mst.AWVALID = valid;
}

8.3 Module Integration

Modules are instantiated with new. Interface compatibility is checked at compile time:

module Top (clk, rst, uart_tx, uart_rx) {
    uart = new Uart(baud_rate=115200);
    dma  = new Dma();
    dma.mst = uart.slv;
}

9. Generics and Parameterization

All parameters are typed, supporting default values:

module Fifo #(Width: UInt = 8, Depth: UInt = 16) (
    clk:   In<Clock>,
    wdata: In<UInt[Width]>,
    rdata: Out<UInt[Width]>,
    full:  Out<Bool>,
) {
    let mem: UInt[Width][Depth];
}

10. Verilog FFI

Existing Verilog modules are accessible through a clean foreign function interface:

extern "verilog" {
    module VerilogFifo #(Width: UInt = 8, Depth: UInt = 16) (
        clk: In<Clock>,
        din: In<UInt[Width]>,
        dout: Out<UInt[Width]>,
    );
}

module Top (clk, tx_data, rx_data) {
    let fifo = new extern VerilogFifo(Width=8, Depth=256);
    fifo.din  = tx_data;
    fifo.dout = rx_data;
}

11. Unsafe Implementation Block

The unsafe_impl block provides an escape hatch for PPA-critical regions where explicit hardware control is required:

module CriticalPath (clk, a, b, c) {
    c = a * b;

    unsafe_impl {
        pipeline 2 {
            // explicit pipeline stages for timing closure
        }
    }
}
The compiler continues to verify port types, width consistency, and clock domain coherence inside unsafe_impl. However, functional equivalence to a standard PureHDL implementation is not guaranteed.

12. Assertions

Built-in assertion support enables verification without a separate language:

assert count <= MAX : "Counter overflow";
assert never(count == 0 && valid);
assert always(clk): valid |-> !busy;
