PureHDL — AI-Friendly Hardware Design

补充设计原则：PureHDL 不仅要让人好写，也要让 AI 好生成。

为什么 Rust 比 C 更受 AI 青睐

这不是玄学。LLM 生成 Rust 代码的成功率显著高于 C，原因不是 LLM "更懂" Rust，而是 Rust 的语言设计本身降低了 LLM 的犯错概率。

1. 低熵——同样的事只有一种写法

维度 C Rust
内存管理 malloc/free/calloc/... + 无限种错误方式 所有权 + 借用，编译器保证正确
错误处理 返回值检查/errno/setjmp longjmp/信号 Result<T, E>，统一模式
字符串 char*/char[]/wchar_t/各种编码 String/&str，编码保证

低熵的意义：LLM 生成代码时，选择越少，正确率越高。C 有 5 种方式"正确"地管理内存，但 LLM 选错 4 种。Rust 只有 1 种，LLM 选对的概率高得多。

2. 类型系统就是给 LLM 的说明书

Rust 的类型系统不仅是给人看的，更是给 LLM 的隐式上下文：

Rust 
fn process(data: &[u8]) -> Result<Vec<u8>, ParseError>

LLM 从签名就能推断：data 是只读借用，不会被修改；返回值可能失败（Result），调用方必须处理；失败的类型是 ParseError。

3. 编译器反馈作为训练信号

Rust 的编译器错误信息异常详细。LLM 写 Rust 代码 → 编译器报错 → 错误信息描述问题 + 建议修复 → LLM 修正 → 编译器通过。这个过程产生了大量高质量的错误-修复配对训练数据。

4. 确定性映射

Rust 中：let x = foo() → 要么得到一个值，要么得到一个编译错误。C 中：int x = foo(); → x 可能是未初始化、可能是垃圾值、可能是正确值。

这个怎么应用到 PureHDL

Verilog 在 AI 友好性上的问题不比 C 少。PureHDL 可以从设计上直接解决。

问题 1：Verilog 的熵太高

概念 Verilog 的写法数量 PureHDL 的写法数量
声明信号 reg / wire / logic / 不声明 1 — 自动推断
赋值 阻塞 = / 非阻塞 <= 1 — 只有 =
敏感列表 @(a or b) / @(*) / @(posedge clk) 1 — seq/comb
例化模块 按位置 / 按名字 / 混用 1 — 类型安全的接口组合
FSM 每个工程师有自己的风格 1 — fsm 声明式
位宽 自动截断 / 手动截断 / 扩展 1 — 显式，不自动截断

问题 2：类型系统是给 LLM 的上下文

PureHDL 
// AI 从签名就能知道全部信息
module Fifo #(Width: UInt = 8, Depth: UInt = 16) (
    clk:   In<Clock>,
    wdata: In<UInt[Width]>,
    full:  Out<Bool>,
)

方向显式：In<T>/Out<T> → AI 不用猜信号方向。宽度在类型中：UInt[Width] → AI 不用追踪位宽。时钟域显式：seq(clk) → AI 知道哪些信号在哪个时钟域。

问题 3：确定性综合

PureHDL 的承诺：能编译就能综合。不存在"仿真通过但综合失败"的情况。AI 不需要知道 Verilog 的哪些子集是可综合的——PureHDL 只有可综合子集。

问题 4：模式化构造减少 LLM 的犯错空间

PureHDL 
// 状态机——LLM 只需要枚举状态和转换
fsm(onehot) Controller {
    state Idle, Fetch, Decode;
    Idle -> Fetch when start;
    out.busy = (state != Idle);
}

// 时序逻辑——LLM 不需要关心敏感列表
seq(clk, rst) {
    if rst { count = 0 }
    elif en { count = count + 1 }
}

问题 5：错误信息的可操作性

phdlc 
error[E0301]: width mismatch
  ┌─ src/counter.phdl:8:12
  │

  │       -------- expected 8 bits, got 9
  │

  = help: or widen c: Out<UInt[9]>

对编译器设计的影响

当前可以做的

  1. 错误信息质量 — 从 MVP 开始就写好错误信息，每条错误附带建议修复
  2. 确定性语法 — 没有"两种等价写法"，每种概念一种语法
  3. 模式化构造 — FSM、计数器、FIFO 等常见模式的专用语法
  4. 类型辅助信息 — 类型系统中包含足够信息，不需要额外注释

未来可以做的

  1. AST 层面的 AI 辅助 — phdlc suggest 命令，根据模块签名推荐实现
  2. PureHDL 到自然语言的文档生成 — 从类型签名 + 代码结构自动生成文档
  3. PureHDL JSON 表示 — 导出 AST 为 JSON，方便 LLM 理解和操作

总结

语言 AI 友好度 原因
C ❌ 熵太高，隐式行为太多，错误处理不统一
Rust ✅ 低熵、强类型、确定性、好错误信息
Verilog ❌ 6 种方式写同一个东西、仿真综合不一致、弱类型
SystemVerilog 🤷 加了类型但没解决根本问题，方言分裂反而增加了熵
PureHDL ✅ 目标 单一写法、类型安全、100% 可综合、好错误信息
